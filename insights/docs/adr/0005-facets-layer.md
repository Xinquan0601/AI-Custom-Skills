# ADR-0005：新增会话语义层（facets），与事实层分离

- 状态：Accepted
- 日期：2026-11-05
- 关联：0.3.0；`docs/facets-schema.md`

## 背景

报告的洞察章节（项目领域、互动风格、摩擦、建议）需要每条判断背后有会话级证据。
此前是一次性把 `stats.json` 和抽样消息交给 LLM 写叙事，问题有三：

1. **不可复现**：同一份数据两次写作，分类与摩擦结论可能不同，无法审计；
2. **不可校验**：叙事说「摩擦主要是报错」，但没有任何中间层能证明是哪个会话、哪句话；
3. **口径混杂**：模型直接下结论，事实数字与模型判断混在一起。

Claude Code 的 `/insights` 用五阶段流水线解决这个问题，其中第三阶段
SessionFacets（每会话结构化提取）是叙事质量的来源。本文档记录我们采纳该思路、
但不照抄其数据格式与分类表的决策。

## 决策

新增语义层 `facets`，作为 collect 与 narratives 之间的**可选**步骤：

- `facet plan`：为每个实质会话生成确定性 digest + 提取提示词 + 缓存键；
- `facet merge`：校验模型产出（枚举、逐字证据、必需字段），聚合为 `facets.json`；
- 覆盖率写进报告，未提取的会话不会被当成「没问题」。

边界：

1. facets **不改动** `stats.json` 的任何数字，只做叙事骨架；
2. 分类表按真实数据定制（10 类，含硬件/协议/客户交付），不采用 Claude 的 12 类编程分类；
3. 证据必须逐字出自 digest，转述即拒；
4. 缓存按内容哈希，内容不变不重跑；分类表变更则全部失效；
5. 只对实质会话提取，快速问答跳过，覆盖不足必须披露。

## 备选方案

- **A. LLM 直接通读全部消息写叙事**：不可复现、成本随会话数线性增长、无法审计。否决。
- **B. 纯关键词分类**：实测 74% 可粗分，但 26% 未归类且错分不可解释（如「项目拉新沉淀」被归到文档）。否决作为主方案，保留为开发期预分桶。
- **C. 照抄 Claude Code 的 12 类**：与其数据格式和单 Agent 假设绑定，套在硬件/固件/客户交付上会大面积错分。否决。

## 后果

- 月报多 100 次左右的模型调用；有缓存后只重跑变化的会话；
- 报告多出「目标分布 / 结果达成 / 摩擦类型」以及一条覆盖率说明；
- 0.4 把章节改成以 facets 为骨架，同时保留无 facets 时的降级路径；
- `satisfaction` 是词表信号、`helpfulness` 是模型判断，报告里必须标注为语义层，不能当统计数字。
